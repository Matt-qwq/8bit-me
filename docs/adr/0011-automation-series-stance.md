# 0011 - 自动化集群续篇口径：业务语义定位 + AI 亲和度选型（automation-series stance）

## 状态
Accepted（2026-09-08，作者 grilling 轮次定稿，四轮逐条拍板）

## 背景 / 问题

- 自动化集群已有三篇方法论（RPA 迁移 / 投放数据管道 / 黑盒逆向），站点声音（ADR-0008）定稿为 HR-first 工程化方法论者。
- 新两篇入集群：① XPath 定位纪律 ② RPA 浏览器运行时选型。作者的原始主张高度锐化：`text` 定位最表达业务、`id` 是「垃圾」；
  影刀是「垃圾」、低代码是给 AI 绑手脚、Playwright 全场景最好。
- 两处张力必须先裁决，否则写出来经不起推敲：前端社区主流（data-testid 崇拜 / class-text 脆弱论）与本集群场景（厂商黑盒、
  无钩子可用）冲突；「所有场景 Playwright 最好 + 攻击不会写代码的人」与 HR-first 观感冲突。

## 决策

- **两篇落点**：作品集线·方法论体，`draft: true` 入站（`src/content/blog/`），作者本地验收后按既有流程发布；工具实名
  （影刀 / DrissionPage / Playwright），脱敏边界与既有文章同款（无客户 / 数字 / 政务细节）。
- **XPath 篇主张（业务语义定位）**：RPA 是业务驱动 → 用最能表达业务的锚定位，唯一可见 `text` 第一，`class`/稳定属性
  为可用项，`name`/表单关联次之；动态 `id`、序号 `index`、绝对路径列为禁区。场景前提写明：目标系统不可加测试钩子，
  不取前端 data-testid 教条。
- **选型篇主张（AI 亲和度选型）**：以「AI 生成/维护/迁移的适合度」为第一维度——闭源可视化（影刀）AI 无法生成与维护、
  迁移锁死；开源但 API 漂移（DrissionPage）AI 语料少、版本一换就挂；标准自由代码生态（Playwright）语料足、API 稳、
  协议层可控，全场景最好。`CDP + fetch` 双降险机制（connectOverCDP 贴真实登录态 + 协议直连绕开 UI 点击）保留为
  「运行风险低」论据。
- **争议措辞红线（反低代码）**：火力打「工具与组织方向」（低代码与 AI 开发反向、绑定可视化工具体系就是给 AI 绑手脚），
  **不打人**——「不会写代码又拒绝让 AI 写代码的团队会在产能竞赛中掉队」可写，「人是废物该淘汰」不写（HR 观感事故）。
  锋芒保留，落点转移。

## 考虑过的选项（被弃原因）

- XPath 篇：前端社区教条版（data-testid / role 优先）——黑盒场景无钩子可用，弃；现场取证反教条版——作者否决，
  立场即差异点；原教旨不辩解版——缺场景边界会被内行挑刺，弃。
- 选型篇：决策框架权衡版（按时间线/维护半径给曲线）——作者否决，「AI 开发只需要谁最好、谁最适合 AI」；冷静版
  「不存在最完美」——作者否决，结论就是 Playwright 全胜；攻击业务人员的人身化措辞——HR 读感事故，弃。
- 落点：站外平台草稿——作者确认入 8bit-me 作品集线。

  术语「业务语义定位」「AI 亲和度选型」已入 CONTEXT.md 术语表。
