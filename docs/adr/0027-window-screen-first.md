# ADR-0027: 首屏整扇窗——窗铺满首屏、hero 内容下移成第二章

日期：2026-09-26 状态：已定稿 关联：ADR-0024（真窗化·凹洞）、ADR-0025（工位化）、ADR-0026（章节转场）、ADR-0020（窗外世界）

## 背景
作者 2026-09-26 复审时提了两句：「我其实要的是首页是整个窗，把左边的 hero 移到后面」，
随后定案：「**hero 就挪到下一章**」（并在「hero 自己占一章 / 并进关于章」里选了**自己占一章**，
在「工位留左下 / 搬右半屏 / 拉宽铺满」里选了**搬右半屏**）。

当时的口径（ADR-0024）是**室内墙上的凹洞**：墙在四边都不贴视口、洞只占视口 ~52%×75%、
左缘用 `HERO_GUTTER: 0.4` 把 40% 的宽度让给左侧标题。于是首屏是「左栏文字 + 右半扇窗」的
双栏构图——窗是配景，不是主角。作者要的正相反：**首屏就是窗本身**，站点标题/说明/工位
整体往后挪一章。

## 决策
- **首屏 = 一整扇窗**：新增 `src/components/sections/Window.astro`（`<section id="window">`，
  **零 DOM 内容**，墙/窗框/窗外世界/天气全在 BgFx canvas 上画）。`windowSpec` 反转成：
  **窗的外缘 = 视口四边**（`wall.top = wall.side = 0`，框带 FRAME 18 画在玻璃之外，
  外缘正好贴视口边），玻璃内缩 = FRAME，下区 = 窗台 + `BOTTOM_GAP: 4`。
  桌面与窄屏**同一套几何**（旧的窄屏 84% 居中档删除）。
- **hero 内容下移成第二章** `#hero`（id 不变，避免动打字机/工位那一大套 `#hero` 作用域
  的 CSS 与脚本）：标题 / tagline / intro / 三盘卡带 / 站况读数 / 工位静物全在，一处没删。
- **工位与窗解绑**：`deskSpec` 不再从 `win` 派生（`GAP_WIN` / `LIFT_FRAC` 删除），改成
  `x0 = round(w × 0.52)`、宽 = `BASE_W`、`top = clamp(round(h × 0.8), 240, 1600)`。
  **工位住右半屏**：文字在左、场景在右，与旧的「窗在右」同构图，站点老排版一根手指没动。
- **世界只住首屏**（这条不变），但「首屏」的锚点从 `#hero` 换成 `#window`：
  `worldAlpha` 按 `#window` 的可见度算（窗/景/天气裁剪共用），`.bgfx-scrim` 顶边 = 它的底边。
- **工位另开一扇门**：新增 `deskAlpha`，按 `#hero` 的可见度**两侧对称**淡入淡出
  （`1 − |heroTop| / (0.5h)`）。旧口径里桌/CRT/灯挂在 `worldAlpha` 上，随窗一起消失；
  窗搬走后那样会「进了第二章反而看不见工位」。`drawDeskRoom` / `drawWarmLight` 内部读的
  仍是 `worldAlpha`，调用处临时换成 `deskAlpha`（换门比给两百行绘制代码改参数名安全）。
- **打字机改成「这一章进视口才打」**：加载时 hero 在第二屏（屏外），旧实现在加载时就打完，
  用户滚下来只能看到打完的字。改成 `IntersectionObserver(threshold 0.5)` 触发；
  内联兜底脚本的揭幕判据从 `dataset.tw !== 'done'` 改成 `!== 'on' && !== 'done'`
  ——否则首屏那 3 秒一到就会把还没开始打的字揭幕。
- **导航「首页」指向 `#window`**（首屏 = 页首）；hero 那一章不进导航（与旧版一致）。
- **章节转场首炮改成 `window → hero`**（ADR-0026 的 `isFullCeremony`）：首屏现在是 window 那一章。
- 铭牌（标题/说明/状态）左缘改成**实测 `.container` 左缘**、宽 = 桌面宽——它以前是
  「贴墙、右缘让开窗洞」，窗搬走后改为「左栏文字与右栏工位等宽隔空相对」。

## 后果
- **ADR-0024 的「凹洞语法」在首屏退役**：框贴视口边、没有墙、没有洞深阶梯的「墙内进深」
  语境。这是作者明示的反转（「首页是整个窗」），不是回归旧版——框剖面（外缘阴影/框面/
  内缘受光）、洞深阶梯、窗棂、窗台、月光带、盆栽**全部保留**，只是它们现在贴着视口边画。
  ADR-0024 否决过的「只有屏幕四边一条装饰带、窗棂悬在半空」那种画框式仍不成立：窗棂在洞内、
  框有剖面、阶梯逐级变暗。
- 首屏顶部 ~58px（nav 高度）盖住框带与天顶——nav 是实心 bar，可接受（作者看过的三张
  候选图就是这个样子）。
- 洞深阶梯画在玻璃之内（总厚 12），所以可见景宽 = 洞宽 − 24；`tests/unit/window-room.spec.ts`
  按此守「阶梯不吞掉景色」。
- 「世界只住首屏」的锚点变了：任何按 `#hero` 找世界的代码都要改成 `#window`
  （BgFx 的 `worldAlpha`、scrim 顶边；`tests/e2e/world.spec.ts` 的判据跟着改）。
- 工位现在住右半屏 → 旧的「桌右缘让开窗框外缘（桌不进洞）」约束随窗搬走而消失，
  该单测换成「桌住右半屏 + 桌宽 = BASE_W + 桌完全在视口内 + 桌沿高从视口高派生」。
- 打字机的 LCP 账不变：h1 仍是本页 LCP 元素，只是它现在在第二屏（首屏是 canvas）。
  「逐行揭幕」这条优化原样保留。
- 视差基准从 `scrollY × 0.3` 改成 `−heroRect.top × 0.3`：旧式是「首屏从文档顶开始滚」
  的位移量，搬到第二屏后会变成「一进屏就被推下去一截」（实测 `--plate-bottom` 因此算出
  1345px，整块文字被推到屏外）。

## 不做
- 不给首屏加任何 DOM 文字（作者明示「hero 挪到下一章」；首屏就是景）。
- 不把 hero 并进「关于」那一章（作者选了「自己占一章」）。
- 不做「工位拉宽铺满」——物件之间会出现 ~218px 的空档，作者选了搬右半屏。
- 不复活 `core` 机箱模式、不碰主题单档（ADR-0021 不动）。
