# 0008 - 首页文案定位与站点声音（homepage positioning & site voice）

## 状态
Accepted（2026-09-01，多轮质询定稿：站点文案优先 / HR 读者 / 工程化方法论者定位 / 7+2 条文本清单全批）

## 背景 / 问题

- 首页文案合计约 200 字，此前是「技术规格腔」：hero intro 罗列技术特性（content collections / GB 四色 palette…），
  meta description 是特性清单，about 讲写作 pipeline——访客 5 秒扫不出「这人是干什么的」。
- 站点定位「长期博客 + 8-bit 实验场」；站点声音服务于作品展示与长期内容双线，但「站点完全变成简历附件」是红线。

## 决策

- **首页唯一读者 = HR/面试官**：5 秒内必达「能力方向 + 证据入口」；8-bit retro-experiment 保持为差异化外壳
  （由 hero kicker 与全站视觉/交互气质承担，不进文案长段）。
- **定位主张 = 工程化方法论者（composite）**：5 秒句「把乱摊子收敛成体系」；
  证据链 = 博客方法论三篇（RPA 迁移 / 投放数据管道 / 黑盒逆向）+ 对应项目卡。
- **素材排序**：工作成果 > 项目 > 人格线；**脱敏边界与既有文章同款**——方法域可见（RPA / 数据管道 / 逆向），
  客户与敏感细节只进简历，不上站。
- **文案面 = site copy 全量**：tagline / meta description / hero intro / about / skills 脚注 / contact 引导语；
  blog 空态与 404 说明后置。

## 考虑过的选项（被弃原因）

- 读者人选：路人/好奇访客（人格线）——HR 扫一眼未必 get 能力，弃；双层职能（frame + evidence）——执行成本高、
  定位含混，作者直接选 HR-first。
- 定位选项：数据与自动化专家（domain）——证据最硬但行业细节暴露面大、需先定脱敏边界；逆向/系统破解者
  （differentiator）——记忆点最强但偏离主职、HR 不当交付能力看。两者均弃，选中证据链最长且脱敏最安全的 composite。

## 后果

- 全站未来文案与文章语气继承此声音；blog 文章优化分支挂起，等声音落地后再开。
- 站点文案草稿先本地预览验收（作者确认），验收后单独 commit。
- 「站点完全变成简历附件」仍为红线：HR-first 只作用于首页文案，博客正文保持脱敏方法论化。
