# 内容优先：停止视觉/插图方向的扩张投入

2026-09-11 作者定稿。触发事件：作者提出把 `/lab/warehouse-layers/` 从横版（5 阶段横排）改成竖版（5 层自下而上堆积木），agent 按 archify 的列式布局限制做了竖版原型（`viewBox 470×720`，左列 5 层 + 右列纪律，见文末原型记录）。作者看过竖版原型后否决整个方向，理由是：

> 纯静态就是最好的，你把图做得再好，别人也不一定看，收效甚微，页面也会变卡，博客的核心还是在于文字。

决策：**插图（article figure）与 `/lab` 交互图册两条投入线就此封顶，不再扩张**；站点重心回到文字（文章 + site copy）。

## 边界（这条管什么、不管什么）

**管**（不再做的新增/改造）：
- `/lab` 图形的形态重做（横改竖、重排、换画法）——含已经评估过的「竖版 dataflow」路线
- 文章静态插图的造型重绘（像素化芯片座 / 加装饰层 / 提精度的路线）
- 为「让页面更花」而新增图册条目：**新文章默认不配图**，确有非图不可的表达时用 markdown 字符图（```flow 围栏）处理，不新造渲染层、不引第三方图库
- 视觉路线图文档里尚未开工的图形条目（`docs/plans/visual-roadmap-*.md` 中与插图/图册相关部分视为冻结）

**不管**（继续有效，不受本决策影响）：
- 既有的视觉铁律（装饰层预算、线层级、媒介不混用、排版度量）——任何 UI 改动仍受其约束
- 已落地的动效与交互（hero 打字机、CRT 转场、BgFx、CursorFx、像素滚动条）不因本决策回退或简化
- 已上线的 2 张 `/lab` 图：**保留现状，不删不改**；其守线（`tests/unit/lab.spec.ts`、`tests/e2e/lab.spec.ts` 等）继续留在回归链里跑
- 6 张文章插图当日稍后由作者改判「换成 markdown 渲染的逻辑图」（见 ADR-0019）：旧 SVG 管线（`diagram-art.ts` / `ArticleFigure.astro` / `figure` 字段）整体删除，内容改写成 markdown 字符图
- 排版/可读性相关度量（`typography-metrics-v1.md` 四道门禁）照旧——文字优先恰恰意味着排版指标更重要

**显式 no-s**：
- 不因为「已经投入过了」而把竖版原型推进（沉没成本不构成理由）
- 不把「图更好看」当作文章质量的替代物：文章质量判据是内容与写作层规范（`.pi/skills/blog-writing/`），不是插图
- 不为插图新增依赖、不引入 WebGL/图表库（作者明确点出「页面也会变卡」是反方向）

## 原型记录（已废弃，不入库）

- 产物：`scripts/atlas/specs/warehouse-layers-v.dataflow.json` + `public/lab/warehouse-layers-v.html`（均**已删除**，未进 git）
- 关键实测（供未来若有人重开此方向时省一次调研）：archify 的 dataflow 渲染器是**列式布局**（`stage → x`，`colGap: 215`，最多 5 列；`row → y`，`rowYs` 写死 128/242/356/470/584，最多 5 行），**没有纵向 stage 模式**；竖排 5 层只能用 1 列 × 5 行，列框（泳道）宽度写死 168 → 块只能 150 宽；5 行撑到 y≈640，画布高 ≥720，而站点 iframe 高度是 `clamp(480px,58vh,620px)`（1440×900 下 522px）→ 竖版要塞进帧里必须单独调高帧 + 皮肤加「按高适配」规则，且几何守卫要求块高 ≥78（行距 114 − 78 = 36 ≤ 泳道空白上限 36）
