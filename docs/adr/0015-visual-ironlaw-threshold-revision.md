# ADR-0015：视觉铁律阈值化修订（辩论裁决）

- 日期：2026-09-10
- 状态：已采纳
- 相关：`docs/research/async-area-teardown-2026.md`（本裁决的事实基础）、开发流程文档 视觉设计铁律、`docs/specs/line-hierarchy.md`、`docs/specs/*-acceptance-matrix.md`、ADR-0005

## 背景

作者调研 async-area.com 后提问：「我们的铁律有必要继续保持吗？很明显别人的博客做的非常好」。

站点拆解（技术栈 / 路由 / API / 视觉系统 / 性能实测）见 **`docs/research/async-area-teardown-2026.md`**。

就此派了两名独立子代理（互不可见、并行取证）进行辩论：

- **辩方 A（守方）**：铁律继续完整保持。
- **辩方 B（反方）**：铁律应废除或实质放松。

两方各自产出了独立取证报告（A 32.6 KB / B 46.6 KB），B 还附了可复现实验脚本
（async-area 网格纸 A/B 像素统计 + 本站 13 套主题装饰层对比度）。

## 裁决

**铁律骨架保留；四处修订。** 两方均未全胜：

- **B 赢了表述层**：铁律第一条「氛围来自结构，不来自装饰」作为**绝对禁令**是错的——
  它判死本站自己的 6% 网格（实测对底对比度 1.107–1.185）与 14% 扫描线（1.292–1.510）。
  正确形态是**阈值**。
- **A 赢了结论层**：B 的替代方案（对比度阈值、层数 ≤2、遮罩测试）**比现行禁令更严格**，
  不是更松；且 async-area 的五项硬伤（16.4 MB 首屏 / FCP 2.4 s / RM 仅 2 处 /
  390px 布局崩坏 / 素材无许可）与媒介纪律**没有因果通路**。
- **A 输了一处论证**：A 称 async-area 的网格「不是装饰，是层叠语义」——
  B 的像素统计推翻了它（拿掉网格，卡片外背景带从 6 色 / 标准差 3.73 精确退化为
  1 色 / 标准差 0）。

**两方独立达成的共识（本次裁决的核心依据）**：async-area 的「非常好」拆开是
**视觉整体性（纪律）+ 内容密度（产能）+ 游戏化叙事（设计投入）**，
其中内容密度（229 篇 / 581 天 / 100 端点 API / 自研 21 种 block 编辑器）
与本站视觉铁律既无关也不冲突。本站现状 `src/content/blog/` 18 篇（13 已发布 / 5 draft）。

## 修订内容

| # | 修订 | 依据 |
|---|---|---|
| 1 | 铁律第一条改为**装饰层预算**（对比度 ≤1.55:1、层数 ≤2、无语义承载、摘掉后结构线仍 ≥3:1 且不跌）；新增 `texture-budget.spec.ts` + `texture-mask.spec.ts` | B 的 A/B 实验 + 本站自身两层 |
| 2 | `line-hierarchy` 分**四档**（结构线 / 组件描边 / 通电态 / 底纹），每档独立白名单；`border: 3px` 语法断言改**几何断言**（覆盖 outline / box-shadow / height / width / background 线条） | 双方共同发现：文档 15 行「通电 3px」与 26 行「不得出现 3px」自相矛盾；语法契约漏抓 5 处真实 3px |
| 3 | 47 格验收矩阵**要么转成断言、要么删**，保留 ≤8 格纯观感项（发布前勾一次） | B 实测：47 格全部 `[ ]` 未勾，0 个缺陷由它发现 |
| 4 | `开发流程文档` 去掉 styleseed 假托出处，改「引用可溯源」；补**快道/慢道**判据；显式声明「字体栈是站点决策，不是铁律条款」 | ADR-0005 自证该归属「二手转述、未证实」；A 的锐化 3/4 |

## 明确不做

- 不拆正文 Zpix（B 的条款 6）。理由：A 的判定更稳——字体栈是站点决策，与铁律层级不同，
  混为一谈是归因错误；且 B 自认这是可选条款、气质代价不掩饰。改为在 开发流程文档
  显式声明边界 + 保留度量门禁通道。
- 不放松 a11y / 移动端几何 / 对比度 / 性能预算 / 许可合规 / 部署纪律。
- 不引入 async-area 式技术栈（SPA + 全量 UI 库 + Cocos + 前后台同 SPA）。

## 修订过程中额外发现并修复的缺陷

1. **老浏览器回退路径漏改**：`@supports not (color-mix)` 块里的 `--crt-scan` 仍为 `rgba(15,56,15,.18)`，
   而主 token 已在 09-09 从 18% 降到 14%（为保 gb-green 正文 AA 4.66）。无 `color-mix` 的浏览器
   仍会拿到破 AA 的 18%。由 `texture-budget.spec.ts` 的④号断言抓出，已同步为 0.14。
2. **阈值取整陷阱**：预算阈值若写 1.5:1，会把 pico8-dusk（1.510）与 sweetie16（1.503）
   判红，逼着把扫描线从 14% 再降到 13%——而 14% 正是为保 AA 定的值。故阈值定为 **1.55:1**，
   真正防「装饰抢结构」的是**防倒挂比 ≥2.0×**（实测最低 2.90×）。
3. **遮罩判据的表述修正**：初稿写「隐藏装饰层后结构线几何与对比度**变化 = 0**」——
   实测为假（装饰层本身是 scrim，摘掉后对比度会**上升**，如 /blog 97.53 → 105.1 亮度差）。
   正确不变量是「摘掉后仍 ≥3:1 且**不跌**」，已写入测试与文档。

## 后果

- 装饰层不再被「禁令」判死，而被「预算」约束——**净效果是收紧**（此前本站两层底纹
  靠文档表格里的数值自律，现在由单测逐主题计算）。
- 线元素登记从「先登记再写代码」改为「同 commit 登记」，去掉顺序性阻塞；
  漏登记由几何断言兜住。
- 铁律从「信仰」变为「可推翻」：推翻判据见辩方 A 报告的 J1–J6
  （前置检查净收益为负 / 某约束在 ≥10 套主题下无差别 / 页面级无法达标 /
  守线机制失效 / 开销超预算 / 正文可读性硬门槛未达）。
