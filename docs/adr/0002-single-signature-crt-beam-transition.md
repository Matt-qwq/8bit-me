# 0002 — 页面转场改为单一签名「CRT 光束扫屏」，废弃 v2 五形态 P 系系统（accepted, 2026-08-27）

页面转场从 v2 的五形态系统（默认 ZOOM 液晶吸线 + ZIP/CLAMP/TEAR/SWEEP + OFF、▤ 循环按钮、偏好键 `8bitme:trans`）重做为**单一签名形态**：CRT 光束扫屏（出场/关机与入场/开机都是光束向下扫，深色幕布带细扫描线 + 强调色磷光辉光，WAAPI `steps()` 整齿阶跃、高度恒为 16px 整数倍、收尾干净停住、全站常播零 UI）。08-28 深度视觉优化定稿：幕布改**恒定暗场**（gb-0 暗化 30%，浅色主题不再变浅）、光束改**双芯**（白热亮芯+色晕，无尾迹）、运动改**变齿分段**（出先慢后快/入先快后慢，每段整齿对格）、齿高 32→16、覆盖因子 1.3、极小屏缩齿——均只动参数/结构，不改变本 ADR 的签名结论。

**为什么推翻 v2 的 A/B 胜者 ZOOM**：v2 的 ZOOM 曾通过「引擎中性」A/B 原型（丝滑与否是运动语言问题不是技术栈问题），但那是 P 系（Persona）语系的产品。作者 08-27 多轮 grind 明确否决 P 系方向——「不够 8bit」「完全没有电子感」——并要求零闪烁；随后在原型迭代里以「大像素块帘幕 → 百叶窗列滑 → CRT 光束扫屏」三版收敛到本方案。**不是引擎问题，是气质问题**；WAAPI 引擎、`.ptrans-host` reduce 豁免、劫持链接 + sessionStorage 交接等机制保留未动（A/B 结论仍然有效，勿再折腾引擎）。

**考虑过的替代**：① 保留 v2 五形态只做参数打磨（否决：形态多而浅、「像 PPT」）；② P 系多平面斜带视差（一度选中，作者看后否决）；③ 大像素块帘幕（对格验证通过但「不够 8bit」）；④ 百叶窗竖条列滑（加入抖色纹理后被判「更差了，完全没有电子感」）；⑤ Astro View Transitions 引擎（否决：引擎已被证明中性，纯风险无收益）；⑥ 保留形态循环按钮（否决：单一签名 + 零 UI）。

**后果**：`8bitme:trans` 偏好键与循环按钮退役（历史值 'off' 不再被读取，转场恒播）；`prefs.ts` 的 transPref 导出删除；旧表单 CSS 全量移除；原型页 `src/pages/proto-stripe.astro` 与探针不入主分支。若未来想换签名形态，替换 `PageTrans.astro` 的 `build()` 即可——单点、零 UI、无偏好层。
