RPA 运行时选型：AI 亲和度第一，Playwright 全胜

2026-09-08·RPAPlaywright选型AI方法论

选型文章喜欢画权衡曲线：什么场景选什么，各家各好。这个习惯在 AI 写代码的时代该改了——选型只剩一个轴：AI 亲和度（AI 生成、维护、迁移这套代码的顺畅程度）。

结论先行：打代码的 RPA 团队，Playwright 全场景最好，不需要曲线。

本篇分 5 部分。先讲为什么选型轴心变了，再对比影刀、DrissionPage、Playwright 三家。然后解释为什么 Playwright 全胜，含 CDP + fetch 双降险机制；接着用一次真实的平台搬迁说明「搬得出来」这个隐藏维度；最后亮出对低代码的态度。

一、选型轴心：从人上手到 AI 出力

低代码平台的卖点是人人能上手。可 AI 写代码的时代，人人上手不是生产力，而是天花板——产能瓶颈从「团队会不会写码」变成「工具链给 AI 的自由度」。

AI 亲和度有三个子项：生成（AI 见过多少这个 API 的语料）、维护（改完能否自动验证）、迁移（能不能把脚本带离平台）。闭源可视化低代码在这三项上同时归零：脚本锁在私有画布里，AI 无法生成、无法进版本库、无法迁移。让 AI 做低代码，就是「给 AI 绑手脚」。

二、三家对比：影刀 / DrissionPage / Playwright

影刀：快在交付，债在十年

影刀（国产无代码 RPA 平台）录制即用，交付最快，搭建成本最低，这是它唯一的卖点。债在一侧堆满：闭源、平台锁、AI 无法生成与维护，迁移时一切推倒重来。我们自己就迁过一次——把存量流程从影刀 xbot 整体搬进自研 Python 体系。「快」是把维护成本预支给未来。

DrissionPage：不错，但版本在漂

DrissionPage（开源 Python 浏览器操作库）值得肯定：开源、上手快、搭建适中（没有浏览器下载这类心智负担），单机小活很顺手。可惜不同版本之间 API 变化大，AI 语料里旧版写法多，生成的代码常因版本对不上挂在导入或参数上。能维护，但每次升级都像过一遍雷区。

Playwright：标准，所以 AI 最熟

Playwright（微软开源的浏览器自动化框架）胜在标准化：标准 API、语料足、工具链全，版本又稳定。AI 见过的写法最多，生成偏差最小，改完能自动验证。搭建成本略高于 DrissionPage（浏览器下载加驱动管理），但一次到位，此后年年受益。

三、为什么全胜：不需要权衡曲线

权衡曲线存在的理由，是各选项在不同维度各有优势。AI 亲和度这个轴一立，维度被统一：标准 API 意味着 AI 语料最多；版本稳定意味着 AI 生成的代码换版本不挂；工具链全意味着 AI 产出可自动验证。三项同向，没有需要权衡的地方。

「影刀适合快速交付」是最常见的权衡话术。可快速交付一次，维护十年，迁移另算。低代码的「快」，是把维护成本预支给未来；标准代码的「慢半拍」，换来的是 AI 时代最贵的资产：可验证性。

四、CDP + fetch：风险怎么降

说 Playwright 运行风险低，靠的不是牌子，是两个机制。

一是挂接真实浏览器：connectOverCDP（通过调试协议直连已有浏览器实例）让脚本贴在用户已登录的 Chrome 上运行，不是注入式自动化浏览器，反自动化与风控指纹的风险都更低。二是协议直连：能走 fetch / 直接 HTTP 的业务就走协议层，绕开 UI 点击，页面改版不再耦合脚本。

两条机制同一条主线：贴近真实、减少中间层。能走协议的绝不点 UI。

五、迁移：把脚本搬出平台要走几步

选型还有一个隐藏维度：搬得出来吗。这个维度只有真搬过一次才知道它的分量，而它恰好是低代码最贵的地方。

我们把存量流程从闭源平台整体搬进自研 Python 体系，走过一遍完整路径。

第一步是盘点，而不是重写。先把存量流程按调用频次与改动频次排一遍，找出真正值得先搬的那几条。全部搬完是理想，先搬高价值的才现实。

第二步是抽公共层。几十条流程里总有一样的登录、一样的重试、一样的落库。在旧平台上这些是各流程各写一遍，搬迁前先抽成公共模块，迁移量能降一截。

第三步是双跑校验。新旧两套并行跑同一批输入，比对输出。差异分两类：一类是新实现写错了，一类是旧流程本来就有隐蔽问题——第二类的概率比预想高。

第四步才是切换。按流程粒度逐条切，留一条回退路径，别一次全切。

这套路径的重点在于：搬迁成本主要由抽取公共层决定，而不是由流程条数决定。这也是选型时要看的那个隐藏维度——选了一个搬不出来的运行时，等于把后续每一次架构升级都抵押了出去。

六、低代码：AI 时代的反方向

最后把态度说透：不攻击不会写代码的人，攻击的是方向。把产能绑定在私有画布上，与 AI 开发背道而驰；不让 AI 写代码的团队，会在产能竞赛里一批批掉队——掉队的不是人，是方向。

拿筷子喝汤：工具与问题不匹配，产能就漏。低代码兑现「快」的那一刻，就是它锁死维护与迁移的那一刻。

选型不是捡个顺手的工具，而是决定 AI 的产能能不能放出来。Playwright 全胜不是偏好，是 AI 亲和度这个轴的自然结论。这套结论也适用于脚本内部：标准、稳定、可维护，才配得上长期。
