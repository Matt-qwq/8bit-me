8bit-me v1 项目解说：四项 8-bit 实验的落地

2025-08-25·8bit-meproject walkthroughdesign tokens

这篇是 project walkthrough（项目解说）：把本站 v1 的架构与几个 retro-experiment（8-bit 实验）的设计决定讲清楚，并说明 v2 之后哪些被推翻。

先说阅读方式。下文对每条实验都给三件事：当初怎么做的、具体参数是什么、后来为什么改。第三件最重要——一份只讲「我们做对了」的解说没有信息量，被推翻的决定才藏着判断依据。

一、站点结构：两条路由族

v1 只有两条路由族（route）：

  • / 是首页，single-page scrolling（单页滚动），五个 section 作为独立组件：hero / about / projects / skills / contact；
  • /blog 与 /blog/[slug] 是列表与单篇，由 content collections 驱动。

output: 'static'，产物是纯静态文件，直接交给 GitHub Pages。这条决定在 v2 没有变过，理由也说得出：不需要任何服务端逻辑。

静态部署还有一个附带好处，容易被忽略。静态站的构建产物里没有密钥落地的空间——没有 runtime 环境变量、没有服务端函数，就不会出现「密钥漏进前端包」这类事故。这个安全性质是架构送的，不是靠纪律守的。

二、四项 retro-experiment

四项实验的共同点是都想用代码换掉素材文件。逐个说参数与结局。

像素字体

v1 做法：自托管 Press Start 2P（OFL 协议），只覆盖 Latin，中文正文回退系统字体栈。

v2 结局：弃用 Press Start 2P，换成 Zpix。

换的原因不是审美变化，是排版的硬约束。Press Start 2P 只有 Latin 字形，中文必须回退到系统黑体，于是同一行里出现两种字形——英文是像素方块，中文是矢量字，混排割裂。Zpix 含中文字形，全站一种字体，代价是许可与体积要多花心思。后来正文又进一步交回系统黑体，像素体只做标识语言（标题、导航、按钮、标签），这是更深一层的变化。

CRT 扫描线

v1 做法：全站扫描线加轻微闪烁的 overlay 层，pointer-events: none 不挡点击；尊重 prefers-reduced-motion，并提供显式开关。

v2 结局：保留，但层序改了。

改的是一个实测出来的缺陷。扫描线色取自 --gb-3，也就是正文字色，罩在文字上会把正文对比度从 6.02 压到 4.66、次级灰字从 4.56 压到 3.67——后者破 AA。试过联立求解「扫描线透明度 × 灰字比例」，在十三套主题下无可行解，唯一解是透明度降到 4%，等于取消。最后改的是层序：扫描线移到内容之下。

物理上也该如此。真实 CRT 里像素发光亮于扫描间隙，扫描线不该盖在发光体上面。

程序化音效

v1 做法：Web Audio API 合成，点击、悬停、导航三种短音效，零音频文件；静音开关默认开，选择存 localStorage。

v2 结局：保留并扩成六类角色，加中央委托接线。

零文件这条一直没后悔。加三条音效不增加一次网络请求，也不需要核对素材授权——这两件事省下来的时间比写合成代码多。具体的合成细节另篇讲。

代码生成头像

v1 做法：像素数据写成字符串网格，程序绘制成内联 SVG，换真实素材只动一个组件。

v2 结局：保留，并扩到文章封面。

字符串网格的好处不是省素材，是它可测。绘制是纯函数，于是可以断言：输出确定性、左右对称、像素密度在区间内、字符集合法。换成一张 PNG 以后这些断言全部失效，只能靠肉眼看。这个取舍在后面的封面系统里被复用了一次。

三、设计 tokens：从单色到多主题

v1 全站颜色收敛为 Game Boy 四色调色板（GB palette），以 CSS 变量暴露：

:root {
  --gb-0: #0f380f;
  --gb-1: #306230;
  --gb-2: #8bac0f;
  --gb-3: #9bbc0f;
}

派生色统一用 color-mix() 从四色算，不额外引入色相。

v2 把这套结构保留，把取值变成可切换。四色变量不改名，只是从固定值变成由主题注入，于是十三套主题共用同一套派生规则。

这个决定的收益比预期大。后来发现「深色主题里 --gb-3 是亮色，浅色主题里是墨色」，所有派生色自动拿到了正确极性，不需要为主题分叉写两套规则。

同一套 token 结构，从「一种配色」变成「十三种配色」，改的只是数据入口。

四、部署

astro.config 的 site / base 指向 GitHub Pages 子路径，所有内链走 import.meta.env.BASE_URL 拼出的 base-aware URL。

这里有个后来的修正。v1 把 site 写死在配置里，v2 改成只认环境变量：未设 site 时 canonical 与 og:url 分支自动跳过，不会指向错误域名。写死域名的问题在部署到备用通道时才暴露——换域名要改代码，而正确的做法是同一份代码构建两次、域名由构建期决定。

五、成本账

回答最开始那个问题：复古感是不是很贵。四项实验的成本清单大致是这样。

  • 像素字体：一次许可与子集化，之后零成本；代价是全站字形受字体覆盖限制。
  • CRT 扫描线：一层 CSS，代价是它会影响全站对比度，必须纳入配色预算。
  • 程序化音效：一份合成代码，之后加音效只加数据；代价是浏览器的自动播放策略要处理。
  • 代码头像与封面：一个纯函数；代价是造型受字符网格约束。

共同点是首笔投入一次、之后摊薄。更重要的是：每项都留下约束。真正贵的不是实现，是没有约束——扫描线压对比度、字体缺字形、音效忘接线，这三类问题都不报错，只是悄悄变差。

静态站加程序化音效加单色调色板，是把复古感控制在低成本范围内的组合。但比组合更重要的是：每条决定都写得出为什么，也留得下测试。v2 加上的 canvas 动画与交互，用的还是这套方法。
