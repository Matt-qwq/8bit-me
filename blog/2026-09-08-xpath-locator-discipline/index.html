XPath 定位纪律：业务语义优先，技术指纹禁入

2026-09-08·XPathRPA定位器工程纪律

RPA 脚本里最脆的一环，几乎都是定位器（locator，定位页面元素的路径）。点击逻辑错了会报错，数据清洗错了会被发现；定位器写得不稳，脚本不报错，只是「悄悄点错地方」。

今天能跑、明天断，多半是同一个原因：定位器锚在了页面实现细节上，页面一变，契约就裂。

本篇分 5 部分。先立场景前提与定位器本质，再讲业务语义定位（text 第一）。然后列技术指纹禁区清单，接着讲定位器怎么自检，最后给 XPath 的机械法则与它对 AI 写脚本的意义。

一、定位器：业务映射页面的契约

先交代前提：RPA 的目标大多是厂商黑盒系统。无权改前端，没有测试钩子（test hook，为自动化预留的稳定标记），界面还随时被对方升级改版。前端测试社区流行的 data-testid 教条，在这里没有落点——钩子根本不存在。

定位器本质上是「业务概念映射到页面元素」的契约。契约贴近业务语义，页面实现随便改，契约都不变；契约贴近页面实现，页面一抖，契约就裂。所以定位器的第一纪律不是语法，是「选锚」。

二、业务语义定位：text 第一

text（可见文本）是页面里最能表达业务的东西。按钮叫「提交」还是「保存」，要过产品评审，改动成本高，所以它最稳。业务文案是写给人看的，id 是写给机器看的——机器生成的东西，人最难读。

用文本定位的前提

  • 单个文本必须唯一，或能被收窄：同页多个「删除」，先锚稳定容器（表格行、区块），再在子范围内精确匹配。
  • 精确匹配优先于模糊：contains() 容易误伤（「删除」命中「删除中」），优先 normalize-space(.)='提交' 的整段比对。

class：可用项，非首选

class 混着样式与结构，重构、打包都可能变。只有含稳定业务语义的前缀（如 btn-submit）值得依赖，随机 hash 类名直接禁用。判断标准一句话：它描述业务，还是描述长相。

三、禁区清单：技术指纹

技术指纹（implementation fingerprint）指那些只属于「这次页面实现」的锚。它们写起来最顺手，坏起来也最彻底。三类，逐条说。

动态 id

id="items_12345" 这类自增或带时间戳的 id，每次刷新都会变。静态可读的 id 是资产，机器生成的动态 id 是负债——不可读，不可维护，刷新即断。

序号 index

//button[1] 把语义真空写进契约。页面在前面加一个按钮，它不报错，而是静默指错对象。「指错比找不到更危险」：找不到会失败重试，指错会带着错误数据跑完整条流程。

绝对路径

/html/body/div[3]/div[1]/form/input[2] 把整棵 DOM 写死。任何一个包装层改动，全链报废。

禁区的共同点，是锚的都是实现细节而不是业务。写它们省十秒，维护它们付十年。

四、定位器要能自检

写完定位器不算完，还得让它能在页面改版后自己报出哪里坏了。这一步最容易被跳过，因为「今天能跑」会给人一种做完了的错觉。

做法是把关键定位器从流程图里抽出来，收成一份具名清单，跑业务前先过一遍。清单里每条给两样东西：一个业务语义的名字，一句存在性断言。名字让人看懂这是哪个环节，断言让机器判定它还在不在。

清单化顺带解决一个更隐蔽的问题：「指错」比「找不到」难发现。找不到会抛错，指错会带着错误数据跑完整条流程。有了清单，就能在断言里加一条「页面里这个语义只允许出现一次」——出现两次时立刻停下，而不是默默点第一个。

自检的成本是每次跑之前多几百毫秒。换来的是改版当天就知道哪几条契约裂了，而不是等业务数据对不上再回头查。

五、XPath 机械法则

# 坏：动态 id + 序号 + 深层链
//*[@id="items_12345"]/div[3]/span[1]

# 好：语义根 + 精确文本
//form[@name="apply"]//button[normalize-space(.)='提交']
  • 先锚稳定根，再写相对短路径：范围越小，改动的波及面越小。
  • 谓词精确收窄：能用属性限定，就不再往下钻。
  • normalize-space() 处理空白，别和真实页面的换行较劲。
  • text() 只匹配直接文本节点；要整段文本用 .，两者别混用。
  • 避免 //*[contains(@class,'...')] 链式深路径，class 用精确语义值。
  • 定位完校验可交互：visible、enabled 都验过，才算「找着了」。

六、对 AI：先立约束，再谈产能

AI 写 RPA 脚本时，定位器纪律就是提示词约束。给 AI 立「业务语义定位、禁技术指纹」的规则，产出的脚本天生可维护；不给规则，AI 会顺手用 index——它扫描页面，天然按序号理解结构。

事实源用协议就不猜，定位源用业务就不用实现。两者都选「不易被实现细节扰动」的那一层。

脚本易碎的第一因，是定位器用了技术指纹。把定位器写回业务语言，页面怎么改都不怕；这纪律对人和 AI 同样成立，它会替你守下一轮改版。
