Agent 能力推演：从路由表到三省六部

2026-09-08·AIAgent思考

素材来源：一场与 DeepSeek 的往返推演（对话链接，2026-09）。本文记录的是那场对话里「我的思考」那条线：只推演，未落地，没有跑过任何系统。

最近在 AI agent 的圈子里，看到有人专门把 skills 往 tool calls 的形态改。skills（技能）是给模型读的操作说明，tool calls（工具调用）是模型返回、由代码执行的结构化调用。同一种能力，从「教模型怎么做」改成「让模型选一个函数、填好参数」，行为会稳很多。

这个方向我在意，是因为它剥开之后跟后端那套老东西长得太像。于是我把整场讨论从头推演了一遍，分五段：工具化剥开是什么；tool 与 prompt 的分界在哪；为什么拆完仍由中间层定胜负；内容一大为什么得加丞相；最后停在一个没验证的猜想上——系统不够用，该让谁辩论。

一、工具化剥开：是一张软路由表

Skills 工具化，字面是把「怎么做」写成长文塞进提示词，改成「能做什么 + 参数契约」暴露成函数。模型只负责选并填参数，执行由宿主代码接管，参数有 schema 校验，一次还能并行或链式调多个。这些收益都很实在。

我的第一反应是一句反问：那不就是加一张路由表吗？模型承认，但补了一句：这是软路由。传统路由的 key 是字符串，走 if-else；AI 路由的 key 是语义，决策者是模型自己读描述后做的判断。说白了，模型成了一个「读着路由表做决定的路由器」。

规模一大，新问题就来了：把几百个技能的描述全塞进上下文（context），token 会爆。于是改成两段式——先按触发词召回 top-k 候选，再把候选描述交给模型精排。这就是我后来总结的那句：AI 先调一个 tool 拿候选，再全给 AI 决策。

但召回可能漏。候选里没有正确答案时，模型只能矮子里拔将军，产生幻觉路由。所以必须给模型一个合法出口：拒识（reject），允许它明说「都不合适」。骨架到这里就齐了：路由表加召回，再补一个拒识出口。

二、边界：能不能写代码，不是分界线

剥完第一层，我继续压：那不就是能写成代码的进 tool，写不成的进 prompt 吗？听起来干净，反例马上来。

比如总结一份 PDF。表面看全是代码：读文件、调模型。真把它整个做成一个 tool 却会翻车——总结到什么粒度、哪句算核心，由模型说了算，代码控不住。

有意思的是我的第一反应不是「这不该写成 tool」，而是拆：把 PDF 读成文本是稳定代码，进 tool；怎么总结是判断，留给 prompt。一句话：tool 当搬运工和计算器，不当思考题。

拆完也没到终点，因为两层中间长出了一个新角色。

三、拆完以后：效果由中间层决定

能力一旦拆成「工具取料 + 模型思考」，模型看到的就不再是全貌，而是中间层喂给它的那一勺。中间层怎么筛、怎么拼、怎么贴标签，直接决定模型看到的是全貌还是残片。翻车姿势就三种：

  • 头尾截断：只把开头 500 字喂给模型，模型对着看不到的结尾瞎编；
  • 报错直传：把系统报错原样塞给模型，模型不会修，只会编一句「网络不太好」圆场；
  • 拼接丢归属：两段结果不贴来源就拼一起，模型把张三的工资安到李四头上。

拆到这一步，判断就变了：大模型都差不多，agent 之间真正的差距在中间层。追问自然变成——中间层的规则谁写、谁来保证它自己不出错？

四、内容一大：subagent 只摘录，丞相先质疑

单个 agent 拆得再干净，也有体积上限。几百页的文档，一个上下文装不下，注意力还会在中间段迷失。直觉是开几个 subagent（子代理）并行读。

直接切块派活会崩：每个 subagent 只看一段，回来各说各的，没有人见过完整的因果链，拼起来等于盲人摸象。所以得两级——底层 subagent 只做摘录：抽实体、抄关键句、不做判断；顶层裁决者拿着全部摘录做关联、做回答。

到这里我又压了一句：那不就是加一个丞相，信息上呈前先质疑吗？细想还真是，丞相要查三件事：

  • 查信源：数字出自表格比出自叙述更可信；
  • 查重复：三处同源摘录，别当成三份独立证据；
  • 查相关性：与当前问题无关的奏折，不呈。

五、丞相也拿捏不定：请三省六部上殿

最后一个问题把我卡住了：丞相面对两份都说得通的证据怎么办？最顺手的答案是让提供证据的两个 subagent 对质。我的判断是：不行。

它俩干完活，已经被榨干了，手里只剩各自那一段摘录。让它们辩，只会把同一段话换个说法再说一遍。垃圾辩论只产生垃圾——这句话是我在这段推演里最笃定的一个。

该辩的是上层。丞相拿捏不定，缺的不是信息，是判断。解法是给决策层加不同立场：逻辑派做演绎推演，质疑派专挑动机与漏洞，实证派回原文复核细节。三方各带各的偏斜吵完，丞相做最后裁决。借老祖宗的词：丞相拿不准，该请三省六部上殿，不是让知府互喷。

收束成一条原则：执行层回答「是什么」，决策层回答「为什么」；系统不够用，先给决策层加视角多样性，别给执行层加重复劳动。

收尾：只推演，未落地

上面每一层都是纸上推演，没有一行验证。真要落地，每层都欠着一笔账：多少 skill 才值得上召回？拒识阈值怎么标定？中间层的规则谁写、怎么测？三省六部多跑一轮，延迟和 token 翻多少，值不值？

这场推演真正留给我的只有一句话：agent 的黑话剥到底，剩的是路由、分层、校验与仲裁这几张旧桌子。新词包装老问题，换名字不会让问题消失，只会让问题更难被看见。

所以下次再听到一个新架构名词，我会先问一句：剥开它，是哪张旧桌子？
