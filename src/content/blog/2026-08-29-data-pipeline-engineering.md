# 投放数据管道的工程化

脚本能跑通采集，但「能跑」和「能长期安全地跑」之间隔着一个工程化深渊。
这篇讲一个跨多个投放平台的数据抓取分析工具，如何从「六个相互独立的
脚本」收敛成体系。平台与客户一律隐去，只留方法。

这篇分七部分：先是入口收敛与取数路径，再讲三层风控与登录态纪律，
然后是数仓分层，最后是工程化沉淀。

## 一、注册表：把加工具变成加配置

原来每加一个平台就是一个新脚本，入口散、约束靠自觉。改造后：

- **唯一入口**：一个 `main.py` 同时是 GUI 启动器与 CLI（list / status /
  start / stop / export / analyze / 定时调度）。
- **配置驱动注册表**：每个工具是一条声明式条目，声明它的认证方式、
  数据库路径、入口模块与 GUI 类名。
- **增量协议**：新增工具 = 追加一条声明 + 实现协议三个函数
  （declare / status / start）。这是纯鸭子类型契约，
  没有注册中心，没有继承树。
- **单实例守卫**：落盘锁 + 进程存活探测双保险，「绝对禁止并发」写死。
- **平台层零网络请求**：状态查询只读本地 DuckDB，不许摸网络，
  requests 与 playwright 都不准 import。

## 二、统一浏览器引擎：五条取数路径

不同平台的数据形态天差地别，但取数路径可以收敛成五条，按优先级选：

1. **页面上下文 fetch**（首选）：在页面里 `evaluate` 发请求，
   cookie 与请求头自动携带，最接近人工浏览；
2. **UI 页面驱动**：真实点击 + `page.on('response')` 响应拦截；
3. **requests + HAR**：仅历史引擎（已被真实浏览器取代，见结尾演进）；
4. **报表导出下载**：按 OLE2/xlsx 魔数定后缀，两级表头合并；
5. **DOM 表格抓取**：虚拟滚动表先滚入视口、按行数轮询直到稳定。

共享层归一：CDP 连接真实 Chrome，独立 profile 副本持久化登录态，
WS 僵死自愈，禁止关闭浏览器是铁律。iframe（登录框/业务页）与 XPath
在共享层处理：文本选取走 `normalize-space` 优先、id 兜底，工具不重复实现。

## 三、三层风控（体系核心）

平台的反爬是三层递进的，对应三层防御：

- **L1 身份认证**：cookie 关键字段 + CSRF 令牌三重校验，请求体里的
  token 必须与 cookie 内嵌 token 一致——先证明你是你。
- **L2 行为风控**：IP 限频 + 请求间隔分析 + 页面跳转序列检测 +
  埋点画像——证明你的轨迹像人。
- **L3 算法风控**：实时行为打分 + 蜜罐链接 + 假数据投喂——
  这是最难察觉的一层，也是「看起来一切正常、数据已经错了」的根源。

### 节奏控制：把「像人」工程化

- 请求间隔取对数正态分布：均值 3.2 秒、σ 0.8，下限 1.5 秒、封顶 12 秒；
- 2% 概率随机「发呆」15~45 秒；
- 非线性翻页序列：连续 1~5 页后回跳一页；
- 每 80 页休息 60~120 秒，段落之间隔 5~10 分钟；单日页数设硬上限。

### 犯错姿态：Fast-Fail

重试不超过 3 次，且 302 / 401 / 403 / 业务层失败标志立即中断、绝不重试。
高频重试是比失败更响的风控警报。这条纪律与迁移工程里的「失败要响、
成功要验」同源（见[《RPA 迁移工程化方法论》](/blog/2026-08-29-rpa-migration-methodology)）。

## 四、验证码与登录态：宁可停，不可错

- **验证码三层监听**：网络响应的风控码、页面跳转到验证页、请求前
  DOM 巡检滑块元素——任何一路触发即暂停，落盘进度，通知人工处理。
- **滑块绝不自动拖**：机器轨迹（加速度/抖动特征）必被识破，交给人来。
  5 分钟超时止损，不无限等待。
- **登录态策略**：会话持久化二次免登录；CDP 复用人工登录态；会话失效
  信号（跳转前缀 / 302）出现即全停、不自动重试登录——自动重登是
  账号风险的主要来源。

## 五、反检测：浏览器内 fetch 是终局

对抗自动化检测的终点不是改几个头，而是让浏览器内核替你补齐指纹。
在页面上下文里 fetch，指纹类字段（TLS、HTTP/2、Sec-Fetch）全部由
真实内核生成，埋点事件同样真实产生，等价于人工浏览。再配合覆盖
`navigator.webdriver` 与跳过调试器断点，检测维度基本归零。

## 六、数仓分层：只增不改 + 质量标记

采集只是开始，数据要能信。分层五段：

- **独立源库**：全字段 VARCHAR 保真存储（不预判类型）、同主键
  **先删后插**保证幂等；
- **ETL → ODS**：只增不改、同日整体替换；
- **DWD 视图**：`TRY_CAST` 类型转换 + `_row_valid` 质量标记——
  宁加标记不丢行，脏数据进得去、查得出来；
- **DWS / DIM / META**：汇总、维度、血缘与质量日志；
- **进度表状态机**（待办→进行中→完成/失败）支撑断点续传与状态展示。

报表自动化用了同一套思路：JSON 配置定时调度（串行执行、指数退避重试、
多渠道 Webhook 通知），预置分析 SQL，日报/周报 markdown 自动生成，
独立导出引擎秒级出表、慢速库自动回退。

## 七、演进与沉淀

第一个引擎用的是 requests + HAR 抓包。它快，但 TLS 指纹、请求头特征、
行为节奏全部暴露，数据质量也不可控。演进到真实浏览器加浏览器内 fetch，
是一次降维：把「伪装成浏览器」变成「就是浏览器」。

方法论沉淀成一个闭环：方案文档（为什么弃 requests、七层缺口逐项对照）
→ 策略手册（五路径选型 + 守则全集 + 踩坑清单）→ 守则常量单一真源
（风控参数只在一处定义）。任何一个后来者读这三份文档，就能复现整套
体系的每一个为什么。这与站内其它方法论篇的结论一致：工程化的终点，
是让「为什么」可以追溯（见[《反黑盒系统逆向方法论》](/blog/2026-08-29-reversing-unknown-internal-systems)与[《RPA 迁移工程化方法论》](/blog/2026-08-29-rpa-migration-methodology)）。
