# 给 KDE 写一个 Wallpaper Engine 兼容层

KDE 桌面没有官方视频壁纸能力——但 Steam 创意工坊里最热门的壁纸生态
（Wallpaper Engine，下称 WE）有成体系的视频、网页与实时渲染场景壁纸。
这篇 project walkthrough 讲的是一个 Plasma 6 壁纸插件：不调用 WE 的运行时，
而是 **byte-level 逆向它的壁纸格式**，在 KDE 里原生消费合法的创意工坊内容。

## 三条管线：视频 / 网页 / 场景

插件按壁纸类型走三条独立管线：

- **Video**：QtMultimedia 无缝循环。看似简单，但「无缝」来自对素材元数据的
  精确处理——循环接缝留半帧不行，多一帧不行。
- **Web**：QtWebEngine 渲染网页壁纸。这条线是硬约束最重的一条（见下文平台坑）。
- **Scene**：最硬核的一条——自研 C++ 渲染引擎，直接挂在 Qt Quick 的
  `QSGRenderNode` 上，逐对象复现 WE 的场景描述。

## Scene 的管道有多硬

WE 的场景包是私有容器格式，从壳体到纹理全是黑的：

- **PKGV 容器逆向**：早期参考开源解析项目（repkg）确认结构，后来发现同一
  容器存在两种演化格式（版本 0005 / 0021），分别用**固定偏移**和**魔数扫描**
  两种策略解析，双轨并行走查。
- **纹理链**：容器内纹理经 `TEXV0005 → TEXI → TEXB` 三级封装，LZ4 解压 +
  BCn（BC3/BC1）解码；解码器对「短缺的 BC3 纹理按实际高度自适应解码」——
  官方数据偶尔不自重，解码器必须比官方更宽容。
- **名字链追踪**：一个模型引用哪个材质、材质引用哪张纹理，原生格式不直接给
  答案，要靠 `model → material → .tex` 的名字链逐级解析出来。
- **从纹理里抠视频**：部分场景把 MP4 藏在纹理的像素区域里——提取器逐字节
  扫 TEXV 像素区、把 MP4 字节抠出来落盘缓存，再起一个**独立视频守护进程**，
  经共享内存传帧、上 GL 纹理。绕开后三个麻烦，比想象的省心。
- **兜底回退**：粒子预设纹理不在壁纸包内，回退读取 WE 安装目录的素材——
  说明逆向兼容要兼容到「对方产品目录」这一层。

## 与官方像素对质

场景渲染到像素级，是「像」还是「糊」，肉眼看得见。最磨人的是**多 pass 多次
尝试才能匹配官方输出**：光晕效果（Godrays）在片元着色器里用 24 步
raycast + 噪声抖动 + 距离衰减逼近官方；`sequencemultiplier` 在一份素材里的
含义是帧率而非乘数、模糊半径藏在 `blurprecise` 的 scale 里——这类「字段含义
与名字不符」的逆向事实，靠的是一条条实证，不是文档。

## 平台坑：与 plasmashell 的硬约束共存

KDE 的 `plasmashell` 进程硬编码 `--disable-gpu`，导致：

- WebGL 壁纸全黑；
- 软件渲染回退（SwiftShader）直接崩溃（KDE 讨论区 #15478）。

这条约束逼着插件在所有 GPU 路径上自证「不依赖事件循环外的 GPU」，也逼出了
**免注销热重载**：用 KConfig 的 `_ReloadCount` 机制实现改配置立刷新——开发时
不用每次注销登录，这点在调试着色器时价值巨大。

## 渲染契约：一条管两端的 bundle

图形管线无法在纯 C++ 里闭门造车——插件用 Python（moderngl）做**离线烘焙**：
解包场景、预计算 77 个渲染层与 NDC 变换矩阵，打成 `scene_bundle.bin`，
C++ 侧消费同一份 bundle；「bundle 为唯一渲染契约」，Python 与 C++ 不共享
任何运行时状态，只共享这份文件。这等于给渲染管线立了和 RPA 迁移里
「HAR 为唯一事实源」同款的纪律——**事实只存一处，两端都从它读**。

## 百余条 lesson 的工程笔记

全程沉淀了一套编号分卷的 lesson 笔记（百余条，按阶段分区），三类内容：

1. **格式逆向事实**：对象没有 type 字段、`sequencemultiplier` 其实是帧率、
   `blurprecise` 的 scale 是模糊半径——所有「名字误导人」的实证；
2. **平台坑**：QSGRenderNode 层级规则、`sync()` 深拷贝会重置粒子、QML
   缓存顽固不失效；
3. **工程纪律**：先验环境再写码、一次只改一件事、热重载免注销。

这些笔记既是开发日志，也是给未来的自己（和合作者）写的「领域规范」——
和 RPA 迁移里「每条教训内联成规范」是同一个习惯。

## 结尾

这个插件的价值不在代码量，而在三条线的完整闭环：字节级的格式逆向、
跨进程跨语言的渲染管线、以及与桌面平台硬约束的共存。做完它，逆向一个
私有格式、设计一份跨语言契约、在别人定死的运行时里干活，都成了有完整
方法论支撑的能力。仓库 GPLv2+ 开源：
[Matt-qwq/-plasma-wallpaper-engine](https://github.com/Matt-qwq/-plasma-wallpaper-engine)
——逆向兼容不是偷代码，是读懂格式后做自己的实现。
