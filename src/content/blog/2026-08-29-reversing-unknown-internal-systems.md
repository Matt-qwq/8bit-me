# 没有文档的系统怎么破

很多内部业务系统没有文档、没有 SDK、连后端权限都没有，你只有浏览器和
一个能打开的页面。传统自动化平台的「录屏点击」能跑通 demo，但界面一变就
死、一页页点下去又慢又脆。这篇讲的是另一条路：**直接走协议层**，把黑盒
变成「能写、能验、可复用」的体系。

## 逆向打法的四步

### 1. 静态先行：先知道系统长什么样

不急着点页面。把表单页的前端 JS 存下来（DevTools 导出的脚本动辄数千行），
交给一个 JS 静态分析器解剖，批量抽出九类结构信息：字段控件、联动规则、
内联字典、保存链（从操作到请求封装的调用图 + 固定注入字段）、请求封装、
API 调用清单、校验逻辑、事件绑定、DOM id 规律。

这一步产出的是**结构骨架**：系统有哪些字段、哪些接口、保存时谁带了谁。
信息不对没关系，后面两步会校验它。

### 2. 运行时验证：静态猜不到的，让页面亲口说

骨架里最缺的是**动态参数与编码映射**——哪来的？运行时探针。

在 F12 控制台注入双层 hook：**业务层** hook 请求封装对象（拿到带业务语义的
服务/动作/请求体），**网络层** hook XHR（拿到全量 URL 与原始文本，包括
字典文件）。先注入再操作、刷新即失效——所以探针要设计成「页面加载前注入 +
操作完整体导出」。导出的内容里，字典的 key→文本映射是编码翻译的权威来源。

### 3. HAR 对账：唯一事实源

把操作过程中抓的全量流量导出为 HAR，交给分析器：按请求参数分组接口、
提取 schema、diff「骨架 vs 运行时」的差异、列出副作用接口清单。

铁律：**HAR 是唯一事实源，编码翻译禁止猜测**。猜过一次，错了一整批映射，
从此立规。同一接口带不同标志位会返回完全不同的形态，必须按真实形态分析。

### 4. 视觉兜底：OCR 与 VLM 分工

截图、票据、报错图这类走不到协议层的信息，交给本地视觉：逐字精确用本地
OCR，语义理解用本地视觉模型——先本地后外发，为的是「数据不出内网」，
不是为省钱。

## 加密对抗三板斧

黑盒系统里最常见的「最后一道门」是前端加密参数。通用打法分三步：

1. **diff 请求**：对比相邻请求，找出动态变化的加密参数；
2. **识别编码参数**：判定是 RSA 类（公钥通常来自服务端 challenge）、消息
   摘要还是验证码；
3. **定位加密函数**：导出一段 CPU profile，沿调用链在源码里定位加密实现，
   再还原 sign / encrypt 逻辑——前端加密最终一定在某份 JS 里以明文躺着。

## 产物闭环：解剖报告 + 反查验证

方法论不产出一次性脚本就白做。每解剖一个页面，生成一份**解剖报告**：
字段、联动规则、字典、保存链、API 清单、校验逻辑——给编码直接消费；
另出 JSON 版供脚本自动化对接。

验收闭环直接复用迁移工程里那套纪律：**写入后「保存→反查」回读比对**，
编码字段用 key 比对（文本跨接口不稳定）；编码值要么从字典直取、要么从
源码内联字典取，两边互相对账。

## 安全与边界

这套打法的前提是**授权**：只针对自己工作范围内需要对接的系统，全程
「数据不出内网」——内网素材最小摘取、脱敏后才外发分析、本地模型承担视觉
识别。逆向的是格式与协议，不是绕过安全控制。

## 结尾

「没有文档的系统」在政企内部生态里是常态，而不是意外。这套打法的价值在于
把个人经验固化为**团队可复用的工具链**——静态骨架、动态事实、全量对账、
视觉兜底，四层闭环下来，任何黑盒系统都只是一份等待解剖的报告，而不是一个
只能靠人力点击的谜。
